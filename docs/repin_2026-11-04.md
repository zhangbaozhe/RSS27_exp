# Re-pin to pivopt 01654104 (2026-11-04)

pivopt moves from `94f7c1cd249d4c4fd1d3d64423971e8c786f551a` to master
`016541046c7fd8224b056cc17b5d8d6c1f6f47a0`. The examples are migrated once to
the new API, and `tests/equivalence/` compares the migrated legacy
configurations with reference outputs generated at the old pin.

## Decisions (user, 2026-11-04)

- **Q41 = (b).** Unfreeze `examples/` for this milestone and migrate them to
  the new API. They are frozen again at the new pin.
- **Q42.** The equivalence criterion has five parts:
  - planner inputs are bitwise identical;
  - outputs are bitwise identical where pivopt records a path as bitwise
    unchanged;
  - elsewhere, outputs follow pivopt's approved comparisons: endpoints for
    converged problems, and zero-iteration solves and pullbacks at the same
    trajectory point for finite-budget problems;
  - optimizer work counts are recorded, not compared;
  - all optimizer settings and backward checks are stated explicitly.

  The equivalence sentence in `AGENTS.md` is rewritten to match.
- **Q43.** References cover only the legacy configurations that v9 uses:
  - the gate planning problems of `cpu_gate_certified_training`,
    `cpu_gate_training` and `cpu_gate_probe`, on fixed batches;
  - `examples/arm.py`, `examples/mujoco/arm.py` and
    `examples/mujoco/unicycle.py`.

  The quadrotor, planar-base, polytope and xyz+yaw examples are excluded.
- **Q44.** The references are small `.npz` files with a manifest and hashes,
  generated only at the old pin and committed under
  `tests/fixtures/repin_94f7c1cd/`. Q44 placed the migrated configurations in
  `tests/equivalence/`. Under Q41(b) the migrated configurations are the
  examples themselves, so `tests/equivalence/` drives them and checks their
  declarations against the stored ones.

## What changed

**Pin.** `pyproject.toml` now names the new revision, and
`uv lock --upgrade-package pivopt` relocked it. Only pivopt changed in the
resolved package set. uv 0.13.6 also rewrote the lock to format revision 5:
torch's dependency markers are simplified and one Linux s390x wheel entry is
dropped. The full build at the new pin has backward enabled
(`artifacts/repin_1104/sync.*`).

**Examples.** A three-way merge (`git merge-file`) applied upstream's
`94f7c1cd..01654104` changes to the 12 affected files without conflicts. After
the merge, nine files equal upstream master. The other three
(`cpu_gate_probe`, `cpu_gate_training` and `cpu_polytope_training`) differ
from it only by their documented output paths, plus one call that the
pre-commit hook formatted. Upstream's migration has two parts:
- `FixedTotalTime(total_duration=c, minimum_piece_duration=m)` becomes
  `AllocatedTime(total=Input("total"), fractions=FreeFractions(logit_penalty=0), minimum_piece_duration=m)`;
- each call binds `total` to the constant `c`.

`01654104` changed several defaults, so 14 construction sites now state the
old value explicitly:

| Field | Old default | New default | Sites that relied on it |
|---|---|---|---|
| `OptimizerSettings.past` | 3 | 0 | `cpu_explain`, `cpu_plan_shapes`, `cpu_xyz_yaw`, `planar_base`, `cpu_training` |
| `OptimizerSettings.maximum_iterations` | 500 | 2000 | `cpu_explain`, `cpu_plan_shapes`, `cpu_xyz_yaw`, `planar_base` |
| `LBFGS.memory_size` | 8 | 32 | `planar_base`, `trajectory_problem`, the four `mujoco/` demos, the LBFGS branch of `cpu_training` and `cpu_polytope_training` |
| `BackwardChecks` gates | 1e-2, 1e-6, 1e-14, 1e-6 | all disabled | `cpu_explain`, `cpu_training` |

- **Two LBFGS branches.** `cpu_training` and `cpu_polytope_training` chose
  BFGS or LBFGS by one call expression. Each now constructs the two records
  explicitly, so the LBFGS branch can state `memory_size=8`.
- **Unchanged defaults.** Damping and response defaults of `Implicit`, and the
  other eight `OptimizerSettings` fields, are the same at both pins, as the
  public header diff shows.
- **Provenance.** `docs/upstream_examples.json` now records all 67 files with
  their source hashes at `01654104`, their destination hashes, and the reason
  for every local change (15 files).

**References.** `tests/equivalence/generate_reference.py` ran in an export of
`a9e6f4a`, which has the old pin and the unmigrated examples, with
`tests/equivalence/` copied in (its docstring gives the commands). It produced
10 scenarios in 1.4 MB.
- **Recorded per planner call:** named inputs, the normalized spec and plan
  shape with type names, public results, seeds and pullbacks, and
  zero-iteration repetitions at the returned point.
- **Same-point validity at the old pin:** every repetition returned its
  starting point with 0 iterations. The LinearResponse same-point pullback
  reproduced the recorded pullback bitwise.
- **Limitation for RS:** a FiniteResponse `Resolve` correction re-minimizes
  with the forward settings, which the stopped plan replaces. Its same-point
  record therefore covers the linear predictor only: 0 correction steps,
  against 213 and 199 in the recorded call.
- **Reproducibility:** four generations, with successive versions of the
  recorder, gave bitwise identical arrays apart from wall-clock times. The
  first generation recorded fewer arrays.

## Criteria and how they were applied

The criteria were fixed in `tests/equivalence/test_repin_equivalence.py`
before the first run at the new pin. A hashed copy is kept in
`artifacts/repin_1104/test_repin_equivalence.before_first_run.py`.

- **Envelope.** pivopt's approved endpoint envelope for complete problems:
  f64 rtol 2e-6, atol 2e-7, objective 1e-8; f32 8e-4, 4e-5, 2e-5. The values
  are taken from `pivopt/agent_docs/layout_pinv_time_1102.md` §3, which
  restates `analytic_costs_1101/baseline/evidence/numerical-policy.json`. That
  JSON file is not on this machine. The objective tolerance is applied
  relative to max(1, |old|), following pivopt's "cost scaled" reports.
- **Qualification.** Endpoint comparisons need stationarity ≤ 1e-7 on both
  pins, pivopt's line in `analytic_costs_1101_run.md`. They are applied per
  lane; other lanes are reported.
- **Bitwise rule.** pivopt records only pure energy and quadratic problems as
  bitwise unchanged. Every scenario here has inequality costs, so no scenario
  falls under the bitwise rule.
- **Rule refinement after the first run.** In the first run, 6 of the 10
  scenarios failed only on the positional lists `spec.inputs[i]` and
  `shape.input_shapes[i]`. The new `total` input shifts their positions. The
  lists are now compared by input name. Stored entries must be unchanged and
  in order, and the only addition must be the time input, without a gradient
  and with one value per lane. No tolerance changed. The first-run reports are
  in `artifacts/repin_1104/equivalence_first_run/`.

## Results

**10/10 equivalence scenarios pass. With the 42 existing tests, the suite has
52 passed in 12.1 s** (`artifacts/repin_1104/pytest.*`).

Across all scenarios, every spec field is identical, including every optimizer
setting and backward check. The time migration is as documented, inputs are
bitwise identical, and every lane status and cause is unchanged.

| Scenario | Qualified lanes | Same point, max ratio | Endpoints | Iterations, old → new |
|---|---|---|---|---|
| `arm_hinge`, `arm_relaxed_barrier` | 0/1 | 0 | bitwise | 200 → 200 |
| `mujoco_arm` | 0/1 | 0 | bitwise | 459 → 459 |
| `mujoco_unicycle` | 0/1 | 0 | bitwise | 86 → 86 |
| `gate_training_hinge` | 0/2 | 0 | bitwise | 62, 58 → same |
| `gate_training_relaxed_barrier` | 0/2 | 1.6e-10 | rounding (reported ratio 1.07) | 50, 68 → same |
| `gate_probe_hinge` | 32/32 | 3.5e-10 | envelope 3.5e-10 | same |
| `gate_probe_relaxed_barrier` | 32/32 | 9.1e-6 | envelope 9.1e-6 | same |
| `gate_certified_A` | 0/2 | 1.4e-6 | diverged (reported) | 239, 213 → 243, 224 |
| `gate_certified_RS` | 0/2 | 5.0e-5 | diverged (reported) | 239, 213 → 243, 224 |

Ratios are measured against the envelope, which a value of at most 1 passes.

- **Probe.** In both probe scenarios, every lane qualified, so their endpoints
  and example values (penalty samples, toy sensitivities) were compared and
  passed.
- **Certified A and RS.** Both certified scenarios are finite-budget and
  non-stationary (stationarity about 5e-4). Their paths diverge, and the RS
  corrections take 208 and 177 steps instead of 213 and 199. At the stored
  point, outputs agree within 5e-5 of the envelope, so the divergence comes
  from rounding amplified along the optimizer path, not from a changed
  objective or backward formula. Any legacy certified-training number must be
  regenerated at the new pin.
- **New field.** `BackwardDiagnostics.hessian_null_dimension` is reported as
  0 for both certified pullbacks.

**Other checks.** Five commands ran at the new pin
(`artifacts/repin_1104/cli_smoke.log`):
- `numpy_solve`, `torch_solve` and `jax_solve`;
- `cpu_training --framework torch --steps 3`, which ends with `strict backward
  status: [0]` with the explicit legacy checks;
- `cpu_explain`.

Ruff lint and format checks pass on `examples` and `tests`.
